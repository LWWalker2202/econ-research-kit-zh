# 估计与稳健性

估计看起来是技术步骤，实际上是解释步骤。设定里的每个选择，都在决定这个系数被允许做哪一个比较；每一条稳健性检验，都在决定这篇文章回应了哪一条质疑。这一段做完的标志是：作者能用一段话讲清这个估计是什么，以及它不是什么。

## 什么时候进这里

- 分析样本已经造好，要跑识别备忘录里定死的主设定。
- 聚类层级要选，而且必须在纸面上给出理由，不能按习惯办。
- 审稿人问哪些稳健性检验该放正文、哪些该进附录。
- 计划做异质性分析，必须在分组开跑之前把分组依据定下来。
- 主模型的诊断结果模棱两可，需要一条判断规则，而不是再加一个设定。

## 输入

| 需要什么 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 构造过程有记录的分析样本 | `data-prep`、`sample-flow.csv` | 没有样本流程表就不要估计；先退回 `data-prep` |
| 冻结的主设定 | `identification-memo.md` | 设定没冻结就先冻上，再去看任何估计结果 |
| 已经挂好检验的威胁清单 | `threat-list.csv` | 挂不上威胁的稳健性检验，不进正文 |
| 设计阶段定下的门槛：工具变量强度、预趋势窗口、最小可检测效应 | 设计备忘录、资助方、领域惯例 | 门槛要在估计之前写出来；绝不看完成果再挑门槛 |
| 本次运行使用的软件与命令文件约定 | 项目约定 | 写一个命令文件，重跑要能得到同一批数 |

## 步骤

1. 按冻结的设定重建基准回归，并按事先指定的层级报告系数与聚类标准误。完成条件：表格与备忘录里的设定逐变量对得上。可直接照抄的参考实现在 `templates/estimate_main.py`，Stata 对照实现是 `templates/estimate_main.do`，钉住的金样报告在 `expected/estimation-results.md` 与 `expected/estimation-results.json`：在仓库根目录跑 `python skills/estimation/templates/estimate_main.py --lang zh`，先把 `output/estimation-results.md` 与金样逐行比对、`output/estimation-results.json` 与金样逐字节比对，再改脚本。
2. 给固定效应说理由。每一组都写出它吸收掉哪部分变异、又留下哪部分变异。完成条件：没有任何一组固定效应是因为"惯例如此"才留在里面的。
3. 给聚类层级说理由。写明处理变量在哪一层被指派、误差在哪一层相关，再报告一种替代聚类作为检验。完成条件：备忘录里的聚类句与命令文件用的是同一个层级。
4. 只跑挂得上威胁清单的稳健性检验，其余一律放进附录并各写一行理由。完成条件：正文里的每条检验都在表注里点名了它在防的威胁。
5. 在解释之前先跑诊断：工具变量（IV）看第一阶段强度，双重差分（DiD）看平行趋势与事件研究的领先项，断点回归（RDD）看断点处的密度与协变量平衡，合成控制法（SCM）看捐赠单位的拟合。完成条件：每个诊断都有一条在看结果之前就写好的通过规则。
6. 异质性分析的分组依据取自理论或预注册，不取自数据，并数清检验了几组。完成条件：每个切分在拆分之前就已定义，且点名了所用的多重检验校正。
7. 对确认性检验构成的族做多重检验校正，并点名这个族。完成条件：每一个进入结论的 p 值要么在族内，要么被明确标为探索性。
8. 写结果备忘录，把"这个估计是什么"和"它不是什么"分开写。完成条件：备忘录至少点名一条该设计支撑不了的主张。

## 输出（artifacts）

| 文件名 | 内容 | 给谁用 |
|---|---|---|
| `results-memo.md` | 基准估计、诊断、每条稳健性检验的判定、该设计撑不了的主张 | 合作者与写作环节 |
| `main-table.tex` | 基准列与正文稳健性列，三线表格式 | 论文的结果一节 |
| `diagnostics.csv` | 诊断项、门槛、数值、通过与否、裁定 | 附录与审稿回复 |
| `robustness-index.csv` | 每条检验一行：检验、所防威胁、结果、判定 | 让附录与威胁清单保持一致 |
| `run_estimation.py` | 产出全部数字的命令文件，必要时固定随机种子 | 复现包 |

## 验收

- [ ] 每一个估计都来自同一个命令文件，重跑得到同一个数。
- [ ] 每一组固定效应都有写明的理由，以及它吸收掉的变异。
- [ ] 聚类层级按处理被指派的层级论证，并报告了一种替代聚类。
- [ ] 正文里每一条稳健性检验都点名了它所防的威胁。
- [ ] 每个诊断都有一条在跑诊断之前就写好的通过规则。
- [ ] 异质性分组在拆分之前就已定义，并写明了检验组数。
- [ ] 点名了一个多重检验族，并对每个确认性 p 值施加了校正。
- [ ] 结果备忘录至少点名一条该设计无法支撑的主张。

## 常见失败模式

| 模式 | 表现 | 纠正 |
|---|---|---|
| 大杂烩式稳健性 | 几十个检验，没有一个对应威胁，审稿人看不出哪个有分量 | 只留挂得上威胁清单的检验，其余移进附录并各写一行理由 |
| 按习惯聚类 | 处理在地区层变化，误差却聚在个体层 | 聚在处理被指派的那一层，并把替代层级作为检验报告 |
| 看完成果再挑诊断 | 预趋势窗口恰好是能通过的那个窗口 | 窗口在识别备忘录里定死，结果照此报告 |
| 追星号 | 主设定是在一张网格里按显著性挑出来的 | 事先承诺主设定，把网格画成设定曲线并标出承诺的那一个 |
| 异质性钓鱼 | 分组是拆完样本、发现某一组显著之后才出现的 | 分组依据取自理论或预注册，并写明检验了几组以及校正方式 |

## 与其它 skill 的接口

- 上游：`identification` 交来冻结的设定、威胁清单和聚类层级；`data-prep` 交来分析样本与样本流程表。
- 下游：`tables-figures` 把这些结果排成表图；`report` 把结果备忘录与诊断变成可复现报告；`writing` 用这里划定的解释边界来避免过度主张。
