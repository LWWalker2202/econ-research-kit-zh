# 设定阶梯

回归结果不是一个数字，而是一条路径：每加一级就是多一个决定，真正要紧的是系数在级与级之间走了多远。这张表要在看结果之前写下来，这样"只在某一种聚类下显著"才没机会悄悄变成"结果"。

## 这张阶梯怎么用

- 复制到项目里，改名 `spec-ladder.md`。
- 一级一行，顺序就是实际要跑的顺序：基准打头，之后每次只改一件事。
- 每一级都要写清"相对上一级改了什么"。写"加控制变量"不够，把控制变量点名。
- `python skills/estimation/templates/estimate_main.py --ladder` 会把合成面板的五级表格一次写全；`--step N` 才是跑一级停一级的增量写法。
- 先定哪一级是报告用的那一级。先写下来，才能挡住"看过结果再挑一级"。

## 五级阶梯

| # | 改了什么 | 固定效应 | 聚类层级 | N | R2 | 系数（标准误） | 相对上一级 |
|---|---|---|---|---|---|---|---|
| 1 | 基准，只放处理变量 | | | | | | |
| 2 | 加控制变量 | | | | | | |
| 3 | 聚类到处理层级 | | | | | | |
| 4 | 围绕处理日的事件研究 | | | | | | |
| 5 | 换其他聚类层级 | | | | | | |

## 哪一级是结果

跑之前就写下来：

- **报告的那一级**：进摘要的那个数字。
- **为什么是这一级**：一句话，指回识别阶段。
- **什么会让我改主意**：系数或标准误变化到什么程度，你会停下来重想。

## 一级动了怎么读

- 系数动、标准误不动：加进去的控制变量吸走了一部分处理变异。说清是哪个控制变量、为什么该在。
- 系数不动、标准误动：多半是聚类选择，不是效应的故事。显著性变了，诚实的一句话是"只在按 X 聚类时显著"，不是"显著"。
- 两者同时动：上游出了问题。回识别阶段，别继续加级。

## 这不是什么

- 它不是稳健性一节。稳健性针对的是点名的威胁；阶梯展示的是每个决定做了什么。
- 它不是钓鱼许可证。级数是跑之前写好的，事后补的一级要标明是事后补的。
- 它不能替代事件研究。阶梯说的是平均效应稳不稳，对预趋势一个字都没说。
