# 文献矩阵

## 怎么用这份表

一篇文章一行，六个内容列外加一个标记列。把这份文件复制成你项目里的 `lit-matrix.csv`，删掉示例行。**边读边填**，不要等周末凭记忆补——那样写出来的矩阵，是带作者名字的小说。

## 七列各写什么

| 列 | 写什么 | 别写什么 |
|---|---|---|
| `id` | DOI，或 刊名+年+卷(期)+页，或工作论文编号 | “那篇 Card 的文章”、光秃秃的标题、一个你以后找不到的网址 |
| `citation` | 作者、年份、短标题，按它将出现在参考文献里的样子 | 你没核对过的完整格式 |
| `question` | 这篇文章的问题，一句话 | 这篇文章的标题 |
| `design` | 实际设计加估计量：双向固定效应 DiD、bunching、用了某个具体工具变量的 IV、跑变量是某个具体变量的 RDD | “实证”“定量”“面板数据” |
| `finding` | 方向或幅度，并说明是对哪个结果变量：就业 +3.2%、为负且不显著 | “显著”“有正向影响” |
| `source` | 期刊名或工作论文系列 | “网上” |
| `closest` | 只有一行写 `yes`，其余留空 | 三行都写 `yes` |

## 一个填好的例子

```text
id       : 示例刊甲 2019, 5(2), 11-40
citation : 示例作者甲（2019），某县级工资下限对青少年就业的影响
question : 县级工资下限会不会压低青少年就业？
design   : 双向固定效应 DiD，2004 年改革，县—年面板
finding  : 青少年就业下降 3.2%，效应集中在中小企业
source   : 示例刊甲
closest  : 
```

## 每一行该怎么处理

1. 只从摘要抄来、或者只在别人文章里看见过的引文，在 `finding` 里标 `[待核实]`，在你打开原文之前不许引用。
2. 如果两行都在争 `closest`，说明缺口句还没锐；把缺口重写到只有一行能赢。
3. 被排除的文章另存一个文件，不要混在这张表里。什么都装的矩阵，什么也显示不出来。

## 这份表不是什么

它不是你的读书摘要：它是**一句缺口话背后的证据表**。它不能替代原文，`check_matrix.py` 也不查它的真伪——检查器只读格式。
