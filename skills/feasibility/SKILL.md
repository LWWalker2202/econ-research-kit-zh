# 可行性闸门

可行性闸门是项目里最便宜的一段，也是唯一以"说不"为职责的一段。它的产出不是一个计划，而是一个结论：做、缩小范围后做、或者不做。它留下的每一条文字，都是为了让这个结论在事后可以查证——尤其是在沉没成本开始替相反结论说话的时候。

## 什么时候进这里

- 学生用一句话提出一个题目，但一个数据集都还没点名。
- 导师或审稿人问这个设计撑不撑得住，而这个回答必须写下来，不能只在会上口头讲。
- 流程已经投进去一段时间，团队对"继续做还是换题"意见不一致。
- 手上有一批候选题目要排序，而只有一个能拿到完整流程的资源。
- 预注册或项目申请要求事先写清放弃条件。

## 输入

| 需要什么 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 点明分析单位、处理变量、结果变量和对照的研究问题 | 导师、阅读清单、政策文件 | 先跑 `scripts/preflight.py`；缺的槽一次问完（最多三个问题）；一句话写不出来，说明题目还没成型 |
| 候选数据集及其获取渠道 | `data-dict/`、机构门户、合作者 | 至少列两个备选；没有获取渠道的数据集按不可得处理 |
| 处理是怎么被指派到单位的制度细节 | `domains/*/institutional.md` | 读一手政策文本，核不实的每一条都标 `[待填]` |
| 按人周与算力小时计的预算 | 自己以往项目的账和截止期 | 在评估开始前就把数定下来，不要等题目变得诱人之后再补 |
| 如果做成，这篇文章要主张什么 | 领域惯例、已有文献 | 把主张写成一句话；这句话决定了有意义的效应下限，也就是最小可检测效应 |

## 步骤

1. 跑 `python scripts/preflight.py "<用户的原话>"`，把四槽位表抄进备忘录，每个槽后面标来源（用户给的 / 我推断的）。**缺槽不许进第 2 步**：缺几个就按"最多三个问题"一次问完，停下等回答。完成条件：四槽全部填满，每一项都标了来源，且推断项已获用户确认。
2. 做数据覆盖筛查。对每个候选数据集，把四个字段分别标成"有""代理""无"。完成条件：得到一张数据集与字段的矩阵，没有一个空格。
3. 做获取渠道筛查。为每个数据集记录获取渠道、负责人、申请周期（以周计）。完成条件：每个数据集都有一个周数，以及一个负责提交申请的人。
4. 用一句话写出外生变异（exogenous variation）的来源，句式是"X 在单位之间不同，是因为 Y，而 Y 与 Z 无关"。完成条件：Y 是某项制度、某条规则或某个机械公式，而不是一个行为选择。
5. 把成本拆成三行报价：清洗与匹配、估计、写作。完成条件：给出人周合计与算力小时合计，并能与剩余时间 `[待填]` 直接比较。
6. 在任何后续投入之前把止损判据写出来。每条判据要有阈值和决策规则，例如：两个候选数据集都缺结果变量；威胁清单筛完之后没有一个可信的反事实；申请周期超过剩余时间；最小可检测效应（MDE）大于政策上有意义的效应 `[待填]`。完成条件：至少三条判据，每条要么是一个数，要么是二选一。
7. 给出结论，并点出唯一的约束条件——那个一旦发生就会杀死整个项目的风险。完成条件：结论是"做""缩小范围后做""不做"三者之一，并用一句话点名该约束。

## 输出（artifacts）

| 文件名 | 内容 | 给谁用 |
|---|---|---|
| `feasibility-memo.md` | 结论、四槽题目、数据集矩阵、变异句、成本、约束条件 | 合作者与导师；证明这个结论是拿证据换来的 |
| `feasibility-check.csv` | 每个候选题目一行，列为数据、变异、成本、结论 | 给一批题目排序；以后设计变了再捡起被否掉的题目 |
| `data-access-plan.md` | 数据集、获取渠道、申请周期、负责人、备选来源 | 负责提交数据申请的人 |
| `stop-criteria.md` | 事先承诺的阈值与决策规则，附复盘日期 | 后续环节卡住时打开，用来决定是否放弃 |

- `templates/check_memo.py` 对填好的备忘录做六项机检（四槽位、覆盖类别、止损阈值、结论、约束瓶颈、获取周期），中英文均可；`expected/feasibility-memo.md` 是一份填好的样例，`expected/check-report.txt` 是它跑出来的报告。

## 验收

- [ ] 四槽全部填满，每一项都标了来源（用户给的 / 用户确认过的推断）；没有一项是「我猜的」却没问过。
- [ ] 每个候选数据集在四个字段上都标了"有""代理"或"无"。
- [ ] 每个数据集都有获取渠道、负责人和以周计的申请周期。
- [ ] 变异句能回答"变异从哪来"，且回答里没有出现回归。
- [ ] 成本是按人周和算力小时给出的数，不是文字描述的范围。
- [ ] 至少三条止损判据带有阈值和决策规则。
- [ ] 备忘录以三种结论之一收尾，并点名了约束条件。
- [ ] 备忘录里没有任何数字被当成结论；未核实的数字一律标 `[待填]`。

## 常见失败模式

| 模式 | 表现 | 纠正 |
|---|---|---|
| 数据集许愿单 | 计划里点的数据集，没有人核过到底能不能拿到 | 在任何建模工作之前，先给每个数据集记下获取渠道与申请周期 |
| 拿固定效应当识别 | 写"用固定效应处理内生性"，却说不出变异来源 | 先写变异句；固定效应是拿去变异的，不是造变异的 |
| 成本从中间开始报 | 报价只覆盖估计，而清洗与匹配才是大头 | 清洗与匹配单列成行，各挂一个人周数 |
| 没有止损规则 | 项目拖了几个月，因为没有任何判据能触发停止 | 事先承诺阈值，并在闸门处排一个复盘日期 |
| 沉没成本话术 | 每个质疑都被"这个以后能处理"挡回去 | 把约束条件写在第一页，复盘日再读一遍 |

## 与其它 skill 的接口

- 上游：题目提案，以及 `data-dict/` 里记录的获取事实；被否掉的题目在设计改动之后会回到这里。
- 下游：`identification` 接手变异句和威胁清单的种子；`data-prep` 接手获取计划与覆盖矩阵。

## 领域细节去哪查

- `domains/energy-env/institutional.md`：环境规制如何在地区和年份之间指派处理。
- `domains/labor/data.md`：哪些住户面板或企业面板能同时承载结果变量与处理变量。
- `domains/behavioral/pitfalls.md`：实验室与问卷调查类可行性主张最常遇到的反对意见。
- `data-dict/`：某个具名中国数据集的覆盖年份、汇总层级和获取渠道。
