# 识别策略与设计

识别设计要回答的只有一个问题：与什么相比。处理变量、对照组、外生变异的来源、威胁清单，全部是为了把这个比较固定下来，让另一个研究者拿到同一份数据会得到同一个比较，而不是一个听起来说得通的比较。

## 什么时候进这里

- 可行性闸门给了"做"，现在必须把问题落成一个可估计的设计。
- 手上有了处理变量，但说不出究竟靠它的哪一部分变异识别效应。
- 审稿人写"这个设计可能有内生性"，你需要交一份带检验的威胁清单，而不是一段保证。
- 马上要预注册，必须在看到结果之前把主设定、样本规则和稳健性预案定下来。
- 合作者提议再加一个控制变量或一组固定效应，得有人说清这一项到底在识别什么。

## 输入

| 需要什么 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 点明分析单位、处理变量、结果变量和对照的研究问题 | `feasibility-memo.md` | 退回 `feasibility`；不要在一个点不出比较的问题上做设计 |
| 外生变异的来源：一项政策、一个阈值、一次抽签、一次意外冲击 | 政策文本、`domains/*/institutional.md` | 点名指派机制；确实没有，就把设计如实标成描述性 |
| 数据结构：截面、面板、重复截面，以及处理在哪一层发生变化 | `data-dict/`、码本 | 在写设定之前就定下来；估计量与固定效应都由它决定 |
| 已有文献用了什么设计、审稿人攻击了哪一点 | 阅读清单 | 记下它们的设计与各自挨的批评；涉及页码的判断先标 `[待填]` |
| 目标刊物或资助方要求的预注册字段 | 期刊、资助方或注册平台 | 在估计开始之前，把要求字段抄进 `pre-registration-draft.md` |

## 步骤

1. 用可测量的方式定义处理变量与对照组。处理变量要有定义、有来源、有测量时点；对照组是未受处理且其余方面可比的那批单位。完成条件：只拿着码本，读者就能复现出这两组。
2. 用一句话写出外生变异的来源："X 在单位之间不同，是因为 Y，而 Y 与 Z 无关"。完成条件：Y 是某项制度、某条规则或某个机械公式，而不是一个行为选择。
3. 画出比较。点名反事实、时间窗口和分析单位。完成条件：这句话经得起"与什么相比、在什么时期、在哪一层"三问。
4. 搭威胁清单。写出三到五条具体威胁，每条给出偏误方向、对应的检验或稳健性检验、以及能推翻该设计的那个结果。完成条件：每条威胁三部分齐全，且至少有一个检验用现有数据就能跑。
5. 让样本层级对齐。把处理变量的层级、结果变量的层级和聚类标准误的层级对到同一条线上，并写明处理状态发生切换的单位怎么处理。完成条件：备忘录里有一句话同时点明分析单位与聚类层级。
6. 定死主设定。写出估计方程，并列出每一组固定效应、每一个控制变量各自用掉的是哪部分变异。完成条件：每个控制变量有一行理由；任何吃掉识别变异的控制变量，要么删掉，要么单列成一个设定报告。
7. 在估计之前写完稳健性预案。每一条都写明它在防哪条威胁、什么结果算失败。完成条件：预案里没有任何一条检验找不到对应的威胁。
8. 把设计冻结进 `identification-memo.md`，需要时把主设定抄进 `pre-registration-draft.md`。完成条件：备忘录带版本日期，预注册字段要么填好，要么标 `[待填]`。

## 输出（artifacts）

| 文件名 | 内容 | 给谁用 |
|---|---|---|
| `identification-memo.md` | 变异句、比较句、带检验的威胁表、分析单位与聚类层级 | 合作者与审稿人；后续几个环节的参照文件 |
| `threat-list.csv` | 每条威胁一行：威胁、偏误方向、检验、可推翻的结果、状态 | 在写文章之前追踪哪些威胁已经闭合 |
| `pre-registration-draft.md` | 主设定、样本规则、稳健性预案、开始分析日期 | 注册平台、期刊或资助方 |
| `specification-table.tex` | 主方程，加上固定效应与控制变量的清单及各自用掉的变异 | 论文的实证策略一节 |

- 可跑检查与金样：`templates/check_design.py` 逐项检查设计备忘录是否写全上述六项，`expected/identification-memo.md` 是填好的样例，`expected/check-report.txt` 是钉住的真实输出；在仓库根目录跑 `python skills/identification/templates/check_design.py skills/identification/expected/identification-memo.md`，再把输出与金样逐行比对。

## 验收

- [ ] 处理变量与对照组是按码本定义的，不是按匹配后剩下的样本定义的。
- [ ] 变异句点名的是制度或机械机制，不是一个行为选择。
- [ ] 比较句能回答"与什么相比、在什么时期、在哪一层"。
- [ ] 威胁清单里有三到五条威胁，每条都给出偏误方向、检验和可推翻的结果。
- [ ] 分析单位、处理变量的层级、聚类层级在同一处同时写明。
- [ ] 主设定里的每一组固定效应和每一个控制变量都有一行理由，说明它用掉哪部分变异。
- [ ] 预案里的每一条稳健性检验都点名了它在防的威胁。
- [ ] 备忘录有日期，预注册字段要么填好，要么标 `[待填]`。
- [ ] 备忘录里每条威胁在 `threat-table.md` 里都有一行，且每行的判定是 `cleared`、`weakened`、`binding`、`open` 之一。

## 常见失败模式

| 模式 | 表现 | 纠正 |
|---|---|---|
| 把固定效应当成识别 | 写"控制了个体与年份固定效应"，却说不出变异来源 | 先写变异句；固定效应是拿走变异的，不是造变异的 |
| 装饰性威胁清单 | 威胁写成"遗漏变量""测量误差"这类通称，一条检验都没挂 | 每行强制给偏误方向、检验、可推翻的结果三项 |
| 样本由匹配结果定义 | 处理组与对照组是在丢掉匹配失败的记录之后才划的 | 先按码本划组，再按固定顺序施加样本规则 |
| 控制变量堆叠 | 以稳健性为名加控制，实际吃掉了识别用的那部分变异 | 说清每个控制变量用掉什么变异；用掉识别变异的，删掉或单列报告 |
| 没有目的的稳健性 | 二十个检验，没有一个对应威胁，审稿人看不出哪个要紧 | 只留挂得上威胁清单的检验，其余放附录并各写一行理由 |

## 与其它 skill 的接口

- 上游：`feasibility` 交来变异句和约束条件；`domains/*/institutional.md` 交来指派机制。
- 下游：`data-prep` 按这里定死的定义构造处理组与对照组；`estimation` 跑主设定和挂上威胁清单的那些检验。
