# 数据获取与整理

可复现的论文是在数据整理这一步决定成败的。管住整段的只有一句话：分析样本里的每一个数字，都来自一个从原始文件出发的脚本，没有一个数字来自手工修改。改干净的 Excel 表不是结果，是一条找不回来的决定。

## 什么时候进这里

- 识别备忘录已经冻结，要按它的定义把分析样本造出来。
- 两个数据源要按标识符合并，而匹配率预计会出问题。
- 分析要用的某个变量，在调查轮次或年鉴年份之间改了措辞、改了单位或改了参照期。
- 已经有人手工改过表，必须先从原始文件重建样本，再去估计。
- 复现包或数据可得性声明要求把每一步清洗都写下来。

## 输入

| 需要什么 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 未改动的原始文件，附文件名与校验值 | 机构、调查、供应商，或项目的附件目录 | 把原始文件复制到只读目录并登记校验值；绝不在原地清洗 |
| 每一轮或每一年的码本或变量清单 | 数据提供方；已有条目时查 `data-dict/` | 没有条目就照官方文档现建一份并交回 `data-dict/`（该目录的 README 说明哪些源该建条目）；核不实的名字逐条标 `[待填]` |
| 各来源之间的标识符对照表 | `data-dict/`、官方对照文件 | 没有对照表就如实报告未匹配比例，绝不按名称硬凑匹配 |
| 来自设计的样本规则 | `identification-memo.md` | 先写样本规则再开始清洗；不要拿"合并后剩下什么"反推规则 |
| 分析用的单位与价格口径 | 项目约定、已有文献 | 每个变量定死一个单位和一个价格基准，并把选择写进数据字典 |

## 步骤

1. 冻结原始层。把原始文件复制进只读目录，登记文件名、大小和校验值。完成条件：每个原始文件都有校验值记录，且没有任何脚本往原始目录里写。
2. 在合并之前先核对变量口径。对每个分析变量，逐年记录确切措辞、单位和参照期。完成条件：有一张表按变量列出定义发生过变化的年份，以及每次变化所用的统一规则。
3. 每个来源写一个清洗脚本，各自读原始文件、写一个干净的中间文件。完成条件：跑一条命令就能从原始文件重建中间文件，重跑得到的校验值相同。可直接照抄的参考实现在 `templates/clean_panel.py`，Stata 对照实现是 `templates/clean_panel.do`，钉住的金样日志在 `expected/cleaning-log.md`：在仓库根目录跑 `python skills/data-prep/templates/clean_panel.py --lang zh`，先把 `output/cleaning-log.md` 与金样逐行比对，再改脚本。
4. 筛查缺失与异常值。按变量、年份、分组计算缺失率；把落在文档范围之外的值标出来；不许静默删除。完成条件：每一次删除都是日志里的一行，带删除前后的计数。
5. 按标识符合并并报告匹配情况。把两边未匹配的记录都留在单独的文件里，按年份报告匹配率。完成条件：匹配报告给出未匹配计数，并给每条记录一个原因归类。
6. 统一单位与量纲。在脚本里把每个变量换算到一个单位和价格基准上，不许在表格单元格里换算。完成条件：下游脚本里不再出现任何单位换算系数。
7. 构造分析样本。按固定顺序施加样本规则，并记录每一步之后的样本量。完成条件：有一张样本流程表，给出每条规则施加前后的样本量。
8. 写清洗日志和数据字典。完成条件：只拿到日志、脚本和原始文件的读者，能重建分析样本里的每一个变量。

## 输出（artifacts）

| 文件名 | 内容 | 给谁用 |
|---|---|---|
| `cleaning-log.md` | 每一步、对应脚本、进出文件、行数、决定与理由 | 合作者与复现者；每一次删除的审计线索 |
| `sample-flow.csv` | 每条样本规则施加前后的样本量 | 论文的数据一节 |
| `data-dictionary.csv` | 变量名、标签、单位、来源文件、覆盖年份、统一口径备注 | 对着样本写代码的合作者 |
| `merge-report.csv` | 按年份与按来源方向的匹配率，附未匹配归类 | 附录里替合并辩护的那张表 |
| `run_all.py` | 从原始文件重建分析样本的唯一入口 | 复现包 |

## 验收

- [ ] 每个原始文件都有校验值，且没有脚本往原始目录里写。
- [ ] 每个跨年改过定义的变量都写明了统一规则。
- [ ] 从原始文件跑入口脚本能重建分析样本，并复现相同的校验值。
- [ ] 没有任何分析变量是靠手工改表造出来的；每一个都来自脚本。
- [ ] 样本流程表给出了每条样本规则施加前后的样本量。
- [ ] 匹配报告给出了分年份的匹配率，并保留两边未匹配的记录。
- [ ] 所有单位换算都在代码里，不在表格单元格里。
- [ ] 清洗日志里没有任何一步缺少理由说明。

## 常见失败模式

| 模式 | 表现 | 纠正 |
|---|---|---|
| 手工改表 | 一个改正过的值只存在于某个工作簿的某个格子里 | 把改正写进脚本，连同触发它的条件，然后重新跑出该文件 |
| 静默删除 | 记录在原始与分析之间消失了，却找不到记录 | 每次删除都在日志里留一行，带删除前后计数，按触发的规则分组 |
| 无视定义漂移 | 措辞已经变了的变量，仍被跨轮次合并在一起 | 先建统一口径表；确实没有共同定义，就按时期拆样本 |
| 按名称合并 | 用模糊规则匹配企业名或地名，且不写报告 | 有标识符就用标识符；报告名称匹配率，绝不静默覆盖匹配上的值 |
| 单位混乱 | 同一列里不同年份混着元和万元 | 在脚本里换算，并把换算后的单位写进数据字典 |

## 与其它 skill 的接口

- 上游：`identification` 定死处理变量与对照组的定义以及样本规则；`feasibility` 交来获取计划与覆盖矩阵。
- 下游：`estimation` 读取分析样本和样本流程表；`report` 把清洗日志和入口脚本一起收进复现包。

## 领域细节去哪查

- `data-dict/`：某个具名中国数据集的覆盖年份、汇总层级与已知问题。
- `data-dict/README.md`：数据源不在其中时看这里，它说明哪些源该建条目、哪些源故意不建、怎么建——避免凭空编变量名。
- `domains/labor/data.md`：住户面板与企业面板的合并键与面板结构。
- `domains/energy-env/data.md`：把规制政策挂到单位上所需的地理标识符。
- `domains/behavioral/data.md`：分析之前必须先做的剔除规则与注意力检查。
