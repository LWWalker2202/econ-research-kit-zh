# 清洗决策表

这张表每一行是一个**会改变数据**的动作。先把它填完、给题目负责人看，再去跑清洗代码。事后写的清洗日志只告诉你发生了什么；这张表才是把"发生了什么"变成"谁批准了什么"的东西。

## 这张表怎么用

- 复制到项目里，改名 `cleaning-decisions.md`。
- 一个动作一行，顺序就是脚本的执行顺序。别把两个动作并成一行，拆开才留得下痕迹。
- `进多少行`、`出多少行` 来自一次干跑，干跑不动数据：
  `python skills/data-prep/templates/clean_panel.py --decisions`
- `默认做法` 是没人反对时脚本会做的事。`你的决定` 是全表唯一由研究者本人写的一列。
- 表里没有的动作，不许发生。如果代码做了表里没列的事，是代码错了。

## 六个动作

| # | 动作 | 进多少行 | 出多少行 | 动了什么 | 默认做法 | 你的决定 |
|---|---|---|---|---|---|---|
| 1 | 删除完全重复的行 | | | 行 | 保留第一条，删后出现的副本 | |
| 2 | 删掉关键字段缺失的行 | | | 行 | 先算缺失率，再删 | |
| 3 | 报告面板缺口，不插补 | | | 格 | 只报告 | |
| 4 | 对比率变量在 1 与 99 分位缩尾 | | | 值 | 截断，不删行 | |
| 5 | 在代码里统一单位 | | | 行 | 另存一列，保留原列 | |
| 6 | 标注口径漂移 | | | 行 | 加一列版本号 | |

## 每一行怎么处理

- **接受**：在 `你的决定` 里写 `ok`。默认做法成立，日志里会记下数量。
- **改**：用一句话写出你要的规则，**句子里必须带数字**。"在 5 分位缩尾"是规则；"注意异常值"不是规则。
- **挂起**：写 `open：` 加理由。挂起的行不许带进估计阶段，否则样本就是默认值决定的那个样本。
- **绝不**为了表好看而删行。从表里删掉的一行，是以后谁也找不到的一处改动。

## 一个走通的例子

先跑一次干跑，把数量抄进表里：合成面板有固定种子，数量是精确的，重跑一次数字不变。然后故意改一行——比如把缩尾从 1 分位改成 5 分位——看 `动了什么` 那一列的数字有没有变。数字不动，说明这一行是装饰，不是决策。

## 这张表不是什么

- 它不是清洗日志。日志是脚本跑完写的，这张表是跑之前签字同意的。
- 它不能替代读码本。尤其是第 6 行口径漂移，来源是码本，不是数据。
- 它不是藏判断的地方。每一行都要有数字，有数字就查得动。
