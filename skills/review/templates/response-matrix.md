# 审稿回应矩阵

一条审稿意见一行。在动笔写回复信之前，先把每条意见归成“必须改”还是“准备辩”，这张表就是防止回复信变成一串道歉的东西。

## 怎么用这份表

把它复制到项目里，命名为 `response-matrix.md`。收到决定信的头一个小时就建好，直接照着审稿意见填，趁你还带着情绪、所以还读得仔细的时候。前三列立刻填满；第四列等你真的改完再填，第五列最后填。

表填完，回复信基本自己就写出来了：一行对应信里的一段，顺序也一致。

## 五列各写什么

| 列 | 写什么 |
| --- | --- |
| 意见 | 用你自己的话把这条意见写清，一句话。只有在措辞本身决定怎么答时才引用原话。 |
| 必须改还是辩 | `fix`（改）、`argue`（辩）、`fix and argue`（改了但只改一部分）、`ask`（问清）。意见本身看不懂就用 `ask`，把问题写进信里。 |
| 改在哪 | 节号、页码、表图号。如果你选择辩而不改，就写 `none`。 |
| 一句话说清改了什么 | 写实质，不写姿态。写“样本期从 2001 年延到 2015 年，重跑了第 2 到第 4 列”，不要写“已处理样本期问题”。 |
| 进度 | `done`（已完成）、`drafted`（已起草）、`unresolved`（未解决），一眼看出还剩什么。 |

## 一个填好的例子

| 意见 | 必须改还是辩 | 改在哪 | 一句话说清改了什么 | 进度 |
| --- | --- | --- | --- | --- |
| 样本期太短，覆盖不到改革 | fix | 3.1 节第 9 页；表 2、表 3 | 样本期从 2001 年延到 2015 年，重跑第 2 到第 4 列；系数从 0.352 变到 0.341 | done |
| 平行趋势检验只在正文里提了一句 | fix | 图 2、附录表 A3 | 事件研究挪到图 2，前置期检验连同 p 值一起报告 | done |
| 聚类到企业层面过于保守 | argue | 5.2 节第 21 页 | 同时报告按块与按年聚类；标准误在 0.100 到 0.156 之间，结论不变 | done |
| 论文还应该研究工资 | argue | 第 1 节第 2 页 | 加一句说明：工资是市级口径、处理在企业层面，所以这个设计撑不起这条边际 | done |
| 与最接近的论文相比，贡献不清 | fix and argue | 第 1 节第 3 页与第 6 节第 27 页 | 加一段点名最近的那篇论文与三处差异，并删掉审稿人指出没有支撑的那句话 | done |

## 每一行该怎么处理

- `fix`：审稿人是对的。改掉，然后写清改了什么。
- `argue`：审稿人错了，但你要拿出带证据的论证，不是断言。如果这个论证你三句写不清，多半应该是 `fix`。
- `fix and argue`：改一部分，并说明为什么停在这里。
- `ask`：把问题写进信里，单独编号，并说明两种理解下你各自会怎么做。

整封信一条 `argue` 都没有，读起来像没有判断力；大部分都是 `argue`，读起来像没读报告。

## 这份表不是什么

它不是回复信，也不是用来收“我决定不理”的意见的地方。每一行最后都该是 `done`。投稿时还写着 `unresolved` 的那一行，就是你没回答的一条意见，审稿人看得出来。
