# 审稿与回复

## 什么时候进这里

- 两份审稿意见回来了，决定信写的是返修后再审。
- 要把意见分成必须做、可以辩、应当拒三类，而不是逐条都改。
- 审稿人要一个设计给不出的分析，而编辑要求把理由写清楚。
- 意见要转成合作者能认领、能关掉的任务清单。
- 正在写第二轮回复，第一轮已经拒过的意见这次要保持同一口径。

## 输入

| 需要什么 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 审稿意见原文 | 决定信 | 先向责任编辑要齐全文再动手 |
| 带页码与行号的投稿版本 | 投稿文件 | 重新编译投稿版；位置指针以它为准，不以最新稿为准 |
| 合作者真在用的任务板 | 共享项目看板 | 先建任务再起草回复，避免回复里承诺了没人做的事 |
| 被要求补做的稳健性所用估计与附录 | `output/estimates/` 与 `output/tables/` | 先跑规格再写回复，不能反过来 |
| 刊物关于返修与申诉的规定 | 期刊投稿须知 | 直接问编辑，不假定返修期限 |

## 步骤

1. 把每条意见录入 `review/comments.csv`，列包括：意见编号、审稿人、原文、要求做的动作、分类、工作量、负责人、任务编号。完成条件：行数等于两份意见里意见段落的条数。
2. 给每行定类：必须做、可辩、可拒。必须做包括事实错误、定义缺失、标准误未报告、稳健性检验缺失；可辩包括设定选择、行文框架、补充文献；可拒包括与识别策略冲突的要求、拿不到数据的要求、要你换成另一篇论文的要求。完成条件：每行都有分类与一句话理由。
3. 把必须做与可辩的行转成看板任务，写清验收条件与写入范围。完成条件：每个必须做行都有任务编号与负责人。
4. 给每个可拒的行设计替代方案：一个脚注、一张附录表，或一句把关切回应到数据能支撑的程度。完成条件：替代方案是点名可交付的产物，不是"我们考虑一下"。
5. 写说明信，一页：改了什么、什么没改、每条拒改的唯一理由。完成条件：审稿人读到细节之前，已经在第一页看到全部拒改项。
6. 写按审稿人分段的正文：照引意见（斜体）、回应、修改位置（节、页、行）。完成条件：每条意见编号恰好出现一次，没有一条回应声称改后文件里不存在的修改。
7. 重新编译，把每个位置指针在改后 PDF 上核一遍。完成条件：逐条核过之后，没有指针指向不含该修改的页。
8. 把每条拒改与理由记进 `review/decisions.md`，给编辑看，也留给下一轮或下一篇同设计的论文。

说"不改"而不妥协，套用这个结构：先承认关切，再用一句话陈述设计或数据约束（不道歉、不加形容词），最后指向替代方案。"我们同意若能补充 X，机制证据会更锐利。本文数据没有 Y 的测量，因此 Z 在本样本上不可估计。我们新增附录表 A5 报告 W，在数据可支撑的层面回应了同一关切。"这个句式不说审稿人错了，只说数据能识别什么、不能识别什么。

## 输出（artifacts）

| 文件名 | 内容 | 给谁用 |
|---|---|---|
| `review/comments.csv` | 一条意见一行，含分类、工作量、负责人、任务编号 | 合作者 |
| `review/response_letter.md` | 说明信加按审稿人分段的逐条回复 | 编辑与审稿人 |
| `review/decisions.md` | 每条拒改的理由与替代方案 | 编辑，下一轮返修 |
| `review/revision_log.md` | 逐条修改记录，含节、页、行 | 通讯作者 |
| `manuscript/manuscript_v2.tex` | 修订稿，标注改动痕迹 | 投稿系统 |

- 回复信定稿前跑 `skills/review/templates/check_response.py`；金样输出见 `skills/review/expected/check-report.txt`。

## 验收

- [ ] `review/comments.csv` 一条意见段落一行，行数与手工清点两份意见的结果一致。
- [ ] 每行都标了必须做、可辩、可拒之一，并有一句话理由。
- [ ] 每个必须做行都有负责人与看板任务编号。
- [ ] 每个可拒行都点名了具体的替代产物。
- [ ] 每条意见编号在 `review/response_letter.md` 里恰好出现一次。
- [ ] 每处引用的修改都能在改后 PDF 里定位到真实页码与行号。
- [ ] 说明信第一页内列出了全部拒改项。
- [ ] 每条意见在 `response-matrix.md` 里都有一行，且没有一行还写着 `unresolved`。

## 常见失败模式

| 模式 | 表现 | 纠正 |
|---|---|---|
| 只回应意见的标题不回应具体要求 | 第二轮审稿人把同一点再提一遍 | 在"要求做的动作"列用自己的话重述一遍 |
| 承诺了没人负责的分析 | 返修回来时承诺的部分是空的 | 回复起草前先定任务编号与负责人 |
| 拒改但不给替代方案 | 审稿人读成回避 | 每条拒改配一个脚注、附录表或一句话 |
| 引用过期页码 | 编辑找不到对应的修改 | 定稿编译后再核位置指针 |
| 争论语气而不是实质 | 实质观点在来回中被丢掉 | 先陈述约束，再给替代方案，不评价审稿人 |

## 与其它 skill 的接口

- 上游：`writing` 交出已投稿件与各项声明；`tables-figures` 提供回复里要引用的表图编号。
- 下游：`report` 在返修后重建表图；`estimation` 补跑返修要求的设定。
