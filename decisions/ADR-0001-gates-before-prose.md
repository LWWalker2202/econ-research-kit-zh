# ADR-0001：把规矩做成会挡路的脚本，而不是写在文档里

- 状态 status: accepted
- 日期 date: 2026-11-05
- 相关 related: `scripts/preflight.py`、`scripts/gate.py`、`scripts/review.py`、`scripts/recall.py`

## 背景 Context

到 v0.3.4 为止，这个库的规矩全部写在 `SKILL.md` 里：三条硬规矩、八段确认点、六步交互协议。文档写得很清楚，但**一次都没有真正挡住过谁**。

最直接的证据：2026-11-04 那一场，用户只说了一句“我现在想研究家庭收入情况对阶层认同的影响”，接下来的两小时里助手一次都没有提问，直接派了三个子代理，产出 `lit-matrix.csv`（36 条）、`data-coverage.md`（442 行）、`identification-options.md`（534 行）、`threat-list.md`（329 行）。事后查会话记录，全场 `preflight` 出现 0 次 —— 那时代码还不存在。

同一天还有更早的一次：`交付/01_插件化说明书` 里写了 S0–S5 六步协议，但 skill 只会读 `skills/` 下的 `SKILL.md`，那份说明书在 `交付/`，模型根本读不到。

## 决定 Decision

**凡是“必须停下来”的规矩，一律做成脚本，并且让下一步依赖它的结果。**

- 先问清：`preflight.py`，退出码 1 表示该问
- 每段确认：`gate.py`，退出码 1 表示没确认
- 每步复查：`review.py`，跑不过不许进下一步
- 每次记得：`recall.py`，开新会话第一件事

文档里的规矩保留，但只作为**解释**；判断权在脚本。

## 后果 Consequences

好处：规矩变成可测试的（每个脚本都有失败路径的反例），人可以少记一点事，跨会话也不会从零开始。

代价：多四个脚本要维护；脚本的判断是启发式的（`preflight.py` 靠正则切四槽位），会误判，所以每个脚本都必须打印“它在看什么”，允许人覆盖结论 —— 不许静默通过，也不许静默拦下。

## 被否掉的替代方案 Alternatives rejected

- **写得更严厉一点**：已经试过，v0.3.4 的文档比 v0.3.0 严厉得多，行为没有变化。
- **只在根 `SKILL.md` 里加第 0 条**：治不了跨会话失忆，也治不了“模型觉得信息够了”。
