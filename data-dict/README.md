# 数据字典

## 这个目录是什么

每个数据源一个文件，记的是官方码本里没有、而新手每次都会弄错的东西：确切的变量名、跨轮次改过的定义、合并键、覆盖缺口。

这个目录不是经济学数据源的完整清单。它不可能完整，也不该试图完整。它是一个经验缓存：这里每个文件的存在，都是因为有人已经在这个数据源上赔进去过一周。

所以它从一开始就是开放式的：没有一份"支持的数据源"名单让你掉出去。定死的是下面那套分类程序，而这套程序是完备的——任何数据源，包括你还没见过的、甚至还没被造出来的，都必然落进甲、乙、丙三类之一。一个你从没见过的库不是规则的例外，它正是规则存在的理由。

## 每个条目固定四节

1. `## 基本信息`——中英文全称、简称、维护机构、起始年份、更新频率、观测层级。
2. `## 变量表`——变量名、中文名、含义与口径、典型取值。只收实证论文真正会用的那些。
3. `## 已知问题`——覆盖缺口、跨轮次定义变化、已知测量问题、审稿人常问什么。
4. `## 获取方式`——向哪个机构申请、申请路径、大概的等待周期。写机构名，不写网址：网址会失效，机构名不会。

写条目的五条规矩：不写网址、不写软件版本号、不编样本量、没核实的变量名一律标 `[待核实]`、只写你自己真用过的变量。

## 甲类：中文微观数据，值得新增条目

例如：CFPS、CHARLS、CHFS、CGSS、CHNS、CLDS、中国工业企业数据库、中国海关数据库、CSMAR、Wind。

这些该收进来，因为它们的变量名猜不出来、定义在轮次之间漂移、审稿人也会追问。为其中一个写好条目，等于替以后每个用这个源的人省下同样那一周。

新增之后要把它交回这个目录。缓存的意义就在这里。

## 乙类：国际公开数据库，不要新增条目

例如：World Bank、FRED、IPUMS、Penn World Table、OECD、Eurostat、各国统计局。

这些源自带权威且机器可读的文档。在这里抄一份二手摘要，既不如原件，又会悄悄过期。

真正值得记的不是变量清单，而是坑：用哪种价格基期、哪一版 PPP、某年覆盖范围有没有变、跨国可比性怎么处理。这些笔记写进项目自己的 `data-dictionary.csv`，跟分析放在一起，不放这里。

## 丙类：你自己造的数据，字典就是你的设计

例如：实验室实验、自己做的问卷、爬下来的文本、人工编码的政策文件、访谈转录。

这些没有外部码本，因为在做出来之前它们不存在。所以字典不是"查"出来的，它是设计的一部分：实验程序、随机化脚本、抓取规范、你写给编码员的码本。

记在项目的 `data-dictionary.csv` 里，并且要与预注册和伦理批件保持一致。如果定义在预注册之后改过，那个改动是关于这项研究的一个发现，不是一句杂务。

## 怎么新增一个条目

1. 先搜这个目录。已经有文件覆盖该数据源，就扩写它，不要再建一个。
2. 按上面的分类，判断这个源属于甲、乙、丙哪一类。
3. 甲类：复制四节标题，知道多少写多少，其余标 `[待核实]`。
4. 乙类和丙类：写进项目的 `data-dictionary.csv`，不要在这里建文件。
5. 提交前跑一遍 `python scripts/lint_content.py .`。

## 命名与收录标准

小写加连字符，一个数据源一个文件，不按轮次拆：`cfps.md`、`industrial-firms.md`、`pollution-monitoring.md`。

一个数据源值得写条目，至少满足其中一条：变量名猜不出来、定义跨轮次变过、合并键需要对照表、审稿人经常问。一条都不满足，官方文档就够了，这个目录不必插手。
