# 理论建模与机制设计：审稿人会问什么

下面这些是理论建模与机制设计论文的审稿报告里反复出现的问题。它们并不敌意，问的是同一件事：模型有没有为它的假设挣到资格。每条问题后面给出真正能把它关掉的回应，最后一节列出催生这些问题的失败模式。

## 审稿人常问什么

1. "如果放松甚至去掉那条关键假设，你的主命题会怎样？"
2. "哪一条假设在支撑这个机制？它可检验吗，至少可观测吗？"
3. "这个比较静态的符号是推出来的还是假定出来的？请在正文里给出推导。"
4. "读者凭什么相信你的校准参数，而不是一个更简单模型隐含的取值？"
5. "模型的均衡唯一吗？还是比较静态的符号取决于选了哪个均衡？"
6. "什么样的观测会让你放弃这个机制？如果没有，模型就没有在做实证工作。"
7. "这跟标准模型再加一个摩擦有什么区别？这个添加改变了哪条预测？"
8. "参数 X 的数据矩是在与模型当事人不同的人口上测的，映射关系是什么？"
9. "福利结论对应的政策，政府真的能承诺执行吗？"
10. "当这个摩擦趋于零时会发生什么？如果答案回到教科书模型，就明说，并把距离校准出来。"

## 怎么回应

- 对 1、2：在模型中段放一节简短的稳健性讨论，而不是塞进附录，说明哪些命题在放松后仍成立、哪些依赖该假设。在陈述命题的那一句里点明承载机制的那条假设。
- 对 3：在明确的充分条件下推出符号，并给出它成立的参数区间。符号确实不确定时就说清不确定，刻画边界，而不是挑一边。
- 对 4：给出矩、可行区间，以及主结果在区间内移动时的敏感性。靠来源与稳健性辩护的校准能过这一问，靠"看起来合理"辩护的不能。
- 对 5：在明示条件下证明唯一性，或者写出选择规则并用制度论证，而不是用方便论证。
- 对 6：写出可检验含义、能回应的数据、以及什么结果会构成拒绝。数据存在时，就在论文里做这个检验。
- 对 7、10：把新预测相对嵌套模型定位清楚，并报告极限情形。不改变任何预测的摩擦只是装饰，审稿人会这样读它。
- 对 8：把数据单位到模型单位的映射写出来，包括加总假设，并报告对映射的敏感性。
- 对 9：先看模型里的政策工具在现实制度中是否存在、承诺是否可得。不可得时讨论次优版本，而不是一优福利数字。

## 容易翻车的地方

| 失败 | 在论文里的表现 | 应该怎么做 |
|---|---|---|
| 假设不干活 | 主命题的证明用不到该假设，或它只出现在脚注 | 说明去掉后什么会坏，否则删掉它 |
| 机制与数据脱节 | 故事是口头的，模型给出符号，但没有检验把两者接起来 | 写出能拒绝机制的观测；数据存在就去做 |
| 比较静态符号靠断言 | 摘要里声称符号，正文没有推导 | 在显式充分条件下推导，并报告可行区间 |
| 跳过存在性与唯一性 | 未证明就对"那个均衡"陈述比较静态 | 证明存在唯一，或给出并论证选择规则 |
| 校准把结论"调"出来 | 参数取值恰好让模型对上头条事实，其他矩一个不报 | 分开校准矩与检验矩，两组拟合都报告 |
| 政策结论不可实施 | 最优政策要求政府并不具备的承诺或信息 | 改写成次优结论，并指明哪条约束在起作用 |

这些问题的共同点是：审稿人要的不是更多代数，而是每个假设、每个符号、每个数字是否本来可能不一样，以及如果真的不一样，论文会不会告诉读者。
